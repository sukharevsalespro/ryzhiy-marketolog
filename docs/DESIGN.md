Источник истины: `docs/reference-poster.jpg`, 640 × 1280. Масштаб для desktop 1440: 2,25. Прямое построение по утверждённому источнику, без новой концепции.

## Зафиксированные решения

- Сохраняем последовательность, плотность, переносы заголовков, диагональ фото, масштаб цифр и сетку плаката.
- Шрифты: локальные Roboto Condensed 900 для плакатных заголовков, Golos для текста; рукопись hero — вектор из эталона (см. уточнение ниже). Точное имя шрифта растрового эталона неизвестно.
- Справа от hero рыжее поле до края; кремовая полоса удалена по уточнению владельца. Рукопись без clip-path, целиком в пределах viewport на 1280/1440/1920.
- Единственное фото hero — предоставленный portrait-terrace-1200.webp. Графика блога — SVG растения, ч/б кроп anchor и геометрия по явному заданию.
- Явные дополнения задания: ссылка Подробнее; чёрный полукруг и рыжий квадрат в третьей карточке; форма перед футером; социальные ссылки.
- Кнопка регистрации имеет белую надпись на рыжем по прямому требованию владельца.
- На 390px последовательный поток, фото под текстом с верхней диагональю, элементы управления с доступной областью нажатия.
- Боевой endpoint не используется для тестовых POST. Тестовая копия JS подменяется браузером на локальный endpoint; ответ сервера моделируется отдельно.


## Уточнение по пиксельному наложению

Замеры границ фото (x слева/справа при y полного JPG): 40 → 319/553; 100 → 318/548; 150 → 316/544; 220 → 314/539; 260 → 310/536; 300 → 307/533; 340 → 304/538; 370 → 302/548; 390 → 300/558; 415 → 298/600. Контур реализован CSS polygon в единицах исходного изображения. Нижняя правая часть расширяется вслед за рукой, как в JPG.

Для фото добавлен брендовый multiply-слой opacity .1. Контраст исходного фото компенсирован brightness(1.1). Цифры и CTA откалиброваны отдельно: пиксели цифр около #FD5918, кнопки #FD5A18, фон hero остаётся #FE6C1F.

Метод проверки: screenshot 1440, PIL resize к исходным 640 для анализа; тёмная маска max(R,G,B)<150 в ограниченных текстовых областях. Ширина и высота измеряются по окрашенным пикселям, а не line-box. JSON с координатами и процентами — shots4/pixel-metrics.json. JPEG-сглаживание даёт неопределённость порядка одного пикселя исходника; эти замеры не доказывают равенство рисунка букв.

Сравнения теперь вертикальные, ширина каждой стороны 1440. В каждой паре эталон сверху, вёрстка снизу, без зазора. compare-final.png объединяет три пары: hero с шапкой, середина, блог + футер. Форма отсутствует в эталоне и исключена только из сопоставления секций низа, не из сайта. Дополнительно сохранены overlay-hero/middle/lower.png с прозрачностью 50%.


## Рукопись: векторы из эталона владельца

Рукописные надписи — векторы, снятые с эталона владельца `docs/reference-poster.jpg`. При смене текста понадобится новый вектор.

- `assets/img/hand-bolshe-chem-marketing.svg`: область JPG x=546…637, y=147…255, размер 91×108px; на 1440 — x=1228,5, y=330,75, размер 204,75×243px.
- `assets/img/hand-smysl.svg`: область x=564…617, y=1065…1136, размер 53×71px; на 1440 — примерно x=1269, y=2396,25, размер 119,25×159,75px.

- Три строки, исходный наклон и росчерки включены в SVG-контуры. Повторные CSS rotate/skew не применяются. Позиции привязаны к координатам исходного плаката.

## Правки по приёмочному аудиту: D01, D02, D03, D04 (11.09.2026)

Исходные находки — [DESIGN-AUDIT.md](DESIGN-AUDIT.md). Проверка: headless Chrome 152 на отдельной машине (на сервере браузер не поднимаем), локальный HTTP через ssh-тоннель; 9 страниц × 12 ширин, снимки `shots22/`, замеры кеглей/наездов строк — через iframe-зонд с canvas TextMetrics.

**D01 — на 701–1279px постер был нечитаем (кегль от 7.2px).** Постерная сетка построена на корневом кегле `min(100vw/640, 2.0625px)`: подпись в 6rem становится 12px только при полотне 1280+. Поэтому граница главной перенесена с 700 на 1280: ниже неё работает та же одноколоночная раскладка, что и на телефоне, в колонке `max-width:768px` (полосы, шапка и подвал остаются во всю ширину). Заголовок героя на планшете растёт от ширины колонки (`12.5cqw` / `8.1cqw`), телефонные значения не тронуты. Шапка остаётся телефонной только до 700 — на планшете работает общая десктопная. Правило `@media(min-width:701px) and (max-width:1000px)` для календаря стало недостижимым и удалено. Замеры после правки: минимальный кегль на всех девяти страницах и двенадцати ширинах — 10–11px, горизонтального скролла нет.

**D03 — наезд строк кириллического капса.** Замер ink-метрик Roboto: бревис «Й» занимает 0.913em над базовой линией, выносные «Д»/«Ц» — 0.173em под ней, значит двухстрочный капс требует интерлиньяжа ≥1.087. Реальный наезд был один — `h1` на 404 («СТРАНИЦА» / «НЕ НАЙДЕНА», перекрытие 14.2px на 1440). `.utility h1` и `.utility h2` переведены с .95/1 на 1.09, `.fact-number` на вебинаре — с .9 на .95. Остальные дисплейные заголовки (герой главной, `title-main` вебинара, `/zapis/`) по замерам не пересекаются ни на одной ширине и оставлены в исходной плотной калибровке.

**D02 — на широких экранах полотно 1320 читалось как обрезок фона.** Контентная колонка 1320 — решение владельца (DESIGN-WIDE.md), фотография в эталоне тоже не доходит до правого края. Поэтому выше 1600px цвет полосы отдан самому полотну, а снаружи — кремовый канвас страницы: лист постера получает край вместо обрыва фотографии в бесконечном оранжевом. До 1600 включительно всё как раньше, 1440 — попиксельно.

**D04 — scaleX вместо настоящих начертаний.** `Poster` переведён с трёх статических Roboto Condensed на переменный Roboto (`wdth` 75–100, `wght` 100–900, самохост, кириллица+латиница). `wdth 75` метрически совпадает с Roboto Condensed (замер «РЫЖИЙ» 900/100px: 347.03px в обоих), поэтому базовое начертание не изменилось. Значения оси подобраны замером под прежнюю ширину строки: `.hero-name` 92.3%, `.hero-sub` 77.2%, `.about-copy h2` 86%, `.years b` 77.2%, ряд «Форматы» — 100% на все четыре пункта вместо четырёх разных scaleX. Растяжки на тексте Golos (у него нет оси ширины) сняты. Осталось три сжатия по X: `.hero h1` (0.858 и 0.871) и `.card-three h3` (0.87) — у Roboto нет настоящего начертания уже Condensed, закрыть это можно только сменой гарнитуры (решение владельца).
