# Рыжий маркетолог: защита сайта и заявок 14.09.2026

## Архитектура после изменения

Страницы по-прежнему публикуются из GitHub Pages, репозиторий и CNAME не менялись. Перед Pages добавлен **nginx на сервере BTC `72.56.237.253`**: он добавляет защитные HTTP-заголовки, которые Pages настроить не позволяет.

DNS REG.RU: `@` и `www` → A `72.56.237.253`. Старые записи: четыре A `185.199.108–111.153` для `@`, `www` CNAME `sukharevsalespro.github.io.`. Бэкап DNS — `/root/backups/vibe-fixes-20260914/ryzhiy-dns-before.json` на управляющем бот-хосте. Исходный TTL — сутки: часть резолверов может временно отдавать прежние IP. Обе стороны продолжают отдавать сайт; защитные заголовки появляются после перехода на новый nginx.

Форма теперь вызывает **`https://crm.бигтехноклаб.рф/public/ryzhiy-lead`**. Этот точный nginx-location работает независимо от Next.js и состояния сервиса CRM:

1. Общая nginx-зона ограничивает запросы по реальному адресу соединения `$binary_remote_addr`: стартовый запас 5, пополнение 1 запрос в минуту; лишние запросы — 429 с Retry-After 60.
2. Nginx безусловно подставляет серверный `X-Ryzhiy-Gateway-Key` и направляет запрос в прежнюю YC-функцию `d4eut85le1co28mu0lc6`.
3. Функция проверяет `INGRESS_SECRET` через constant-time сравнение **до обработки тела и отправки**. Прямой вызов без ключа запрещён. `integration=raw` тоже не обходит секрет: подделанный event не знает ключа. Входящие query-параметры на nginx не передаются функции.
4. Существующая валидация, согласие, лимит тела и доставка в Telegram/MAX сохранены.

**Не возвращать проверку IP из event публичной функции как единственную защиту:** режим `integration=raw` допускает произвольный event. Лимит обязан стоять на доверенном nginx-входе.

- Прямой обычный вызов функции — 403. В raw-режиме внешний HTTP 200 оборачивает ответ handler `statusCode:403`; отправки нет. Не считать внешний 200 успешной заявкой.

- Новый nginx до DNS-переключения вернул 200 и побайтово тот же HTML, что Pages. В браузере после headers — без JS/CSP ошибок.
- Версия YC после защиты: `d4ees6e97vu2hasbhqqk`. До изменения `$latest` был `d4e0025li8ur9bl9kql0`; полные метаданные сохранены приватно в `/root/backups/vibe-fixes-20260914/ryzhiy-function-versions-before.json` (содержат env, не публиковать).

## Если отвалилось

- **Сайт 502:** BTC nginx/error.log → TLS origin/цепочка/SNI/GitHub IP. Проверить запрос с Host домена к `https://sukharevsalespro.github.io/`.
- **Сайт у одних со старыми headers:** DNS-кэш; сравнить ns1.reg.ru, 1.1.1.1, 8.8.8.8. Не переключать DNS туда-сюда.
- **Заявка 429:** штатный лимит, подождать минуту. Несколько пользователей за общим NAT делят запас.
- **Заявка 403:** сравнить согласованность secret include на BTC и env `INGRESS_SECRET` последней версии функции; значения не печатать. Открытая до обновления старая вкладка с прямым functions URL требует перезагрузки страницы.
- **Заявка 502/таймаут:** сначала nginx→functions, затем логи YC и прежние Telegram/MAX маршруты. Сам сервис Next.js CRM в доставке не участвует, но доступность **nginx/хоста BTC** теперь нужна.
- **Проблема после обновления функции:** deploy.py обязан передавать INGRESS_SECRET. Не использовать старую команду, которая заменяет env только четырьмя TG/MAX переменными.

## Откат

DNS можно вернуть на прежние A/CNAME из бэкапа — сайт снова идёт прямо на Pages, публикация и **новый URL формы** сохраняются. Защитные заголовки при таком откате пропадут, gateway оставить работающим.

Не откатывать одновременно JS на прямой functions URL и не удалять проверку ключа: это снова откроет спам. Если проблема только CSP, менять `/etc/nginx/snippets/ryzhiy-security.conf`, затем `nginx -t && systemctl reload nginx`.

Для ротации ключа синхронно обновить `.secrets/ryzhiy_ingress_key.txt`, nginx secret include и новую версию YC; не оставлять разные значения. Старый экспериментальный internal limiter и его ключ удалены, использовать только `/public/ryzhiy-lead`.

## Проверка формы после публикации

При финальной проверке отправки обнаружен конфликт: существующий HTML meta CSP разрешал только прежний URL YC и блокировал новый gateway. В connect-src HTML-страниц указан новый точный URL. Заголовок nginx не отменяет meta CSP — обе политики действуют одновременно. Проверять нужно нажатие «Отправить», а не только загрузку страницы.
