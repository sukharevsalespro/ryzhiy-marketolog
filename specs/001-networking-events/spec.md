## Пользовательские сценарии

### С1 — Календарь с реальными событиями (P1)
Посетитель главной видит календарь на месяце ближайшего события и его карточку справа; листает месяцы, видит прошедшие и будущие встречи.
**Проверка**: открыть главную 26.09.2026 → октябрь 2026, выделено 8-е, справа карточка нетворкинга 8 октября.
1. **Дано** сегодня 26.09.2026, **когда** открываю главную, **то** календарь на октябре 2026, карточка «Нетворкинг, 8 октября, 12:00–14:00 МСК», кнопка «Подробнее и тарифы» → `/networking/`.
2. **Когда** жму «‹» до августа, **то** в сентябре выделены 11 и 21, в августе 11; эти дни помечены «прошло» (стиль + текст для скринридера).
3. **Когда** жму на дату с событием, **то** справа карточка этого события; у прошедшего — метка «Прошло», без кнопки записи/оплаты.
4. Листание ограничено: раньше августа 2026 и позже декабря 2026 кнопка неактивна.
5. Вебинар 21.09 остаётся в календаре как прошедшее, ссылка «Подробнее» → `/webinar/`.
6. Без JS видна статичная разметка: месяц ближайшего события и его карточка (как сейчас — сентябрь с вебинаром, только обновлённая на октябрь).

### С2 — Страница /networking/ и запись через мессенджер (P1)
Посетитель читает про формат, выбирает дату и тариф, пишет Валентине с готовым текстом.
**Проверка**: на `/networking/` выбрать 10 ноября и «Спикер» → Telegram открывается с чатом Валентины и текстом «Хочу на нетворкинг 10 ноября, тариф «Спикер»».
1. Страница: описание (дословно), платформа «Контур.Толк», три ближайшие даты с днём недели и временем, три карточки тарифов («Спикер» — три строки тайминга с ценами), текст о регистрации (дословно).
2. Выбор даты — нативные радио, по умолчанию ближайшая будущая; прошедшие даты не выбираются и не показываются в списке ближайших.
3. Кнопки «Написать в Telegram» / «Написать в MAX» у каждого тарифа подставляют «Хочу на нетворкинг {дата}, тариф «{тариф}»».
4. Если мессенджер не принимает текст ссылкой — текст копируется в буфер и показывается тост «Текст скопирован — вставьте в чат» (правило «кнопка не молчит»), затем открывается чат.
5. Плитка «Нетворкинги» в «Форматах» ведёт на `/networking/`.

3. `/networking/` в `sitemap.xml` и `llms.txt`.

## Функциональные требования
- **ФТ-1** События хранятся в одном файле `assets/data/events.json` (id, тип, заголовок, дата/время начала и конца в `+03:00`, url, цена/метка для карточки). **Почему не инлайн-JSON:** события нужны на двух страницах (главная и /networking/) — инлайн дал бы две копии; GitHub Pages отдаёт JSON статикой без сборки, CSP `connect-src 'self'` уже разрешает `fetch`. Статичная разметка и JSON-LD в HTML — неизбежная копия без сборки; её сверяет скрипт-проверка (ФТ-8).
- **ФТ-2** «Прошло» = конец события раньше текущего времени браузера; ближайшее = первое непрошедшее. Никаких выдуманных повторов дат — только записи из файла.
- **ФТ-3** Календарь рендерит выделение и карточку только из `events.json`; зашитое «21 сентября» из `main.js` убрать. Ошибка загрузки → остаётся статичная разметка + `console.error` (не молча).
- **ФТ-4** Несколько событий в одном месяце (сентябрь: 11 и 21) — оба выделены, по умолчанию в месяце показывается ближайшее/последнее по дате.
- **ФТ-5** Визуал — по разделу «Дизайн-направление». Рукописные пометки — только существующие векторы (`hand-bolshe.svg`, `hand-smysl.svg`, `assets/img/notes/*.svg`, напр. `note-s-nulya.svg` у тарифа «Подготовка с нуля»); новые не рисовать.
- **ФТ-6** Адаптив: без горизонтального скролла на 320–3840; приёмка — 390 и 1440 через CDP `Emulation.setDeviceMetricsOverride` с заглушёнными анимациями (грабля из БЗ), плюс 768 и 980.
- **ФТ-7** Шапка, подвал, CSP, Метрика, шрифты — как на других внутренних страницах. Пункт меню не добавляем (пятым на 320 не влезает — решение из БЗ).
- **ФТ-8** Скрипт-проверка (node, без зависимостей): даты/цены в HTML `/networking/`, JSON-LD и статичной разметке главной совпадают с `events.json`.

## Дизайн-направление (арт-дирекция до реализации)
Система — эталон владельца `docs/reference-poster.jpg`, не «по мотивам»: рыжее поле, чёрный узкий капс Roboto Condensed 900, кремовые карточки с тонкими рамками, нулевые/малые радиусы, синяя полоса форматов, чёрный футер; оранжевая крупная цифра даты — главный знак события (как «21 сентября» в карточке вебинара). Новых цветов, шрифтов, теней и рукописей не вводим.

Референсы Refero (26.09, `refero_search_styles` / `refero_search_screens`), что берём:
- **Album Colors** style `99be9294` — постер на оранжевом поле, капс с плотным трекингом, тонкие прямые рамки без теней: обложка `/networking/` (уже в reference-lock сайта).
- **Art In DUMBO** style `33e3087c` — даты списком как в печатной афише, тонкие разделители, оранжевый только для статуса: ритм блока дат, метка «Ближайший».
- **fal.ai /events** screen `adc4e269` — ближайшее событие крупной split-карточкой сверху, прошедшие тихим списком ниже: иерархия ближайшее ↔ прошедшее.
- **Runway /meetups** screen `2beb1f1f` — разделы «Ближайшие / Прошедшие», прошедшие без CTA и приглушены: подача прошедших на странице и в календаре.
- **ManyChat pricing** screen `5c1a397c` + **Tilda pricing** screen `407e4fb2` — цена по объёму строками таблицы с тонкими линиями; три карточки на светлом с оранжевым акцентом: раскладка «Спикера» по таймингу и ряд тарифов.

Композиция `/networking/` сверху вниз (1440):
1. **Обложка** (рыжее поле, как первый экран главной): надзаголовок «ОНЛАЙН-НЕТВОРКИНГ», заголовок капсом, справа/под ним крупная оранжево-чёрная дата ближайшего «8 октября · чт · 12:00–14:00 МСК», кнопка «Выбрать тариф» (якорь к тарифам); фото — существующее (`portrait-*`), кадр по той же диагонали, что на постере.
2. **Формат**: описание дословно, «15–20 участников» вынесено крупной цифрой (как «15+» на постере), кремовое поле.
3. **Даты-«билеты»**: три кремовые карточки с рамкой и перфорацией-линией (CSS, без картинок), крупная оранжевая цифра, день недели, время; ближайшая — чёрная заливка/метка «Ближайший»; карточка = радио выбора даты.
4. **Тарифы**: ряд из трёх карточек равной высоты; «Спикер» внутри — таблица 3 строки «2 мин — 1 500 ₽ / 3 мин — 2 500 ₽ / 5 мин — 3 500 ₽»; «Подготовка с нуля» — акцентная (чёрная), пометка `note-s-nulya.svg`; у каждой кнопки Telegram / MAX.
5. **CTA**: синяя полоса как «Форматы» — текст регистрации дословно + две кнопки мессенджеров.
6. **Прошедшие** (11 августа, 11 сентября): одна тихая строка-список серым, без кнопок. Дальше чёрный футер.

Мобилка 390: одна колонка; обложка — дата под заголовком, фото ниже; «билеты» — горизонтальная лента со scroll-snap (или столбик, если ≤3 карточки влезают без «ужатого десктопа»); тарифы столбиком, «Подготовка с нуля» последней; кнопки на всю ширину, ≥44px; без горизонтального скролла страницы.

Календарь главной: день с событием — оранжевая точка под числом; ближайший — оранжевая заливка ячейки (как 21 на постере); прошедшие — точка и число приглушены (серый), в `aria-label` «прошло»; выбранный — чёрная рамка. Карточка справа — та же `.event`, у прошедшего метка «Прошло», вместо кнопки ссылка «Подробнее».

Скилы на вёрстку: `refero-design`, `ui-ux-pro-max`, `design-taste-frontend`, `impeccable`, `microinteractions`.
