# План: SEO-посадочные (003)

**Вход**: `spec.md` этой папки. **Стек**: статика GitHub Pages, без сборки и без новых зависимостей.

## Решения
- Каждая посадочная — `/<slug>/index.html` (+ при необходимости `/<slug>/style.css`, как у `/pozicionirovanie/`). Общие стили — `assets/css/style.css`, `mobile.css`; новых глобальных компонентов не заводим, берём готовые: `page-band*`, шапка/подвал, `rev-card`/`rev-stage` и модалку оригинала с `/otzyvy/` (скрипт `main.js`), CTA Telegram/MAX с копированием текста и тостом с `/networking/`.
- Шаблон делается один раз на образце A; B–E копируют разметку, меняются только контент и JSON-LD.
- JSON-LD — один `@graph`: `Service` (`provider: {"@id": ".../#valentina"}`, `serviceType`, `areaServed: Россия`, `offers` только при цене от Валентины), `FAQPage`, `BreadcrumbList` (Главная → страница).
- Метрика: существующий `metrika.js`; цели «просмотр URL» по образцу 611666152 + цель на клик CTA.
- Проверка без браузера на VPS: браузерные смоуки — на NVR по рецепту из БЗ проекта (раздел проверки `/networking/`), временные файлы удалить.
- Проверка каннибализации — маленький скрипт `specs/003-seo-landings/check-titles.mjs` (без зависимостей): собирает title/H1 всех `**/index.html`, падает, если главный ключ существующей страницы встречается в title/H1 новой.

## Порядок
1. Вопросы В1–В7 уходят Валентине (через владельца) параллельно с образцом.
2. Образец A → «да» владельца → правки в реестр переделок.
3. C (данные есть частично) → D → B (после В1) → E (после В6).
4. Хвосты за существующими страницами — отдельной мелкой задачей после «ок».
5. Выкатка каждой страницы — только по явному «ок» владельца; после выкатки — sitemap/переобход в Вебмастере, запись в БЗ.

## Риски
- Выдача «распаковка личности» может быть психологической (тесты, самопознание), не маркетинговой — проверить ТОП-10 Яндекса вручную до вёрстки A; если интент чужой — главным ставить «распаковка эксперта» 96.
- Без ответов В1–В4 страницы выходят без цены/формата — конверсия ниже; блоки не выдумываем.
