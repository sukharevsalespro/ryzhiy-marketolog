## Разведка Продамуса (первоисточники)
- **Встроенных уведомлений в Telegram у Продамуса нет.** Раздел «Уведомления» справки: только e-mail, SMS (2–7 ₽/шт.) и URL-вебхук — https://help.prodamus.ru/payform/uvedomleniya/kak-ustroena-otpravka-uvedomlenii-ob-oplate , https://help.prodamus.ru/payform/uvedomleniya/email . Бот Prodamus.Pay — для **приёма** оплаты в Telegram, не для уведомлений — https://help.prodamus.ru/payform/priyom-oplaty/kak-nastroit-priyom-platezhei-cherez-telegram-s-pomoshyu-bota-prodamus.pay . В группу TG — только через вебхук (свой или сторонний сервис, напр. Vakas-tools https://vakas-tools.ru/scenarios/prodamus-telegram/ — отдаёт ПДн покупателей третьему лицу, не рекомендуем). ⇒ **вариант А (только настройка в ЛК) задачу не закрывает.**
- **Вебхук**: POST на URL из ЛК, `multipart/form-data` (по умолчанию; `callbackType=json` — только для ссылок, собранных через API). Статусы: success / canceled / denied. Ответ 200 = принято, иначе повторы; для URL до 7 попыток с интервалами от 3 мин до 24 ч — https://help.prodamus.ru/payform/uvedomleniya/intervaly-uvedomlenii . Подпись — заголовок `Sign`, HMAC-SHA256 с секретным ключом ЛК — https://help.prodamus.ru/payform/integracii/rest-api/instrukcii-dlya-samostoyatelnaya-integracii-servisov . Алгоритм (из рабочего кода katipa): убрать `sign`, листья в строки, рекурсивный ksort, `json_encode` без экранирования unicode/слэшей (products → JSON-список), HMAC-SHA256 hex.
- **Поля** (пример payload, https://github.com/hasenberg41/prodamus/blob/master/README.md): `date, order_id, order_num, domain, sum, currency, customer_phone, customer_email, customer_extra, payment_type, commission, commission_sum, attempt, products[i][name|price|quantity|sum], payment_status, payment_status_description, payment_init`. **Поля «имя покупателя» в примере нет** — есть ли оно в вебхуках ЛК Валентины, увидим только на первом тестовом вебхуке, не выдумываем.
- **Где в ЛК**: вход в ЛК платёжной страницы → нижнее меню «Настройки» → блок «Настройка уведомлений» (можно добавить несколько URL кнопкой «+») и блок «Секретный ключ» (кнопка «Копировать»), затем «Сохранить». Новый ключ выдаёт только поддержка — https://help.prodamus.ru/payform/integracii/rest-api/url-dlya-uvedomlenii-i-sekretnyi-klyuch . Уведомления об успехе уходят после зачисления денег на счёт Продамуса — https://help.prodamus.ru/payform/integracii/servisy-dlya-chat-botov/bot-t .
- **Тест**: в настройках ЛК есть тестовая отправка уведомления, из карточки платежа — повторная отправка вебхука (страница «Как устроена отправка…»). Параметр `demo_mode=1` описан для ссылок через API; работает ли он на готовых ручных ссылках payform — **не проверено**.

## Сценарии
### С1 — успешная оплата (P1)
1. **Дано** покупатель оплатил любую ссылку ЛК Валентины (вебхук общий на весь ЛК — придут и оплаты вне сайта), **когда** Продамус шлёт вебхук `payment_status=success` с верной подписью, **то** в TG-группу и MAX-группу приходит:
   `💳 Оплата: {товар} — {сумма} ₽ · {имя, если есть} · {телефон} · {email} · заказ №{order_num или order_id}` + время МСК. Пустые поля — «—». Несколько товаров — через «; ».
2. Функция отвечает 200, если доставил хотя бы один канал.
### С2 — повтор того же вебхука (P1)
Тот же `order_id` повторно в пределах живого инстанса → 200 без второго сообщения. Если дубль всё же прошёл (холодный старт / второй инстанс) и `attempt>1` — в сообщении пометка «(повтор уведомления)».
### С3 — чужой/битый запрос (P1)
Нет/неверная подпись → 403, ничего не шлём. Прямой вызов функции без ключа гейта → 403. Не POST → 405.
### С4 — неуспешный статус (P2)
`canceled`/`denied` → 200, в группу не шлём (только строка лога). **Вопрос владельцу**, см. ниже.
### С5 — оба канала упали
Ответ 502 → Продамус повторит по своему расписанию.

## Требования
- ТР-1 Подпись проверяется до любой отправки, `hmac.compare_digest`; секрет только из env `PRODAMUS_SECRET`.
- ТР-2 Вход только через `location = /public/ryzhiy-pay` на BTC с серверным ключом (как у лида); заголовок `Sign` проходит до функции.
- ТР-3 Логи без ПДн: только `order_id`, статус, сумма, результат каналов. (В katipa-образце телефон/почта в логе — не переносить.)
- ТР-4 Код и тесты без сети; паритет подписи — тест на фиксированном векторе, сверенном с katipa `prodamus_sign()`.
- ТР-5 Изменения `ryzhiy-lead` не ломают: 15+5 существующих тестов зелёные.
