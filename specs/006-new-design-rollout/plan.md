# План: перевод оставшихся страниц на новый дизайн (006)

**Вход**: `spec.md` этой папки. **Стек**: статика GitHub Pages, без сборки и без новых зависимостей. **Ветка**: `new-design`; каждая волна — своя ветка от неё, в main только по «ок».

## Проверка по конституции
- п.1 роли: реализация — сабагенты, главный агент ревьюит кропы; цифры объёма без источника не называю (см. «Объём»).
- п.2 не угадывать: тексты/цены/отзывы только из текущих страниц; пустое — вопросом (spec §11).
- п.3 референсы: Refero MCP + скилы до вёрстки; эталон — главная и мастер-группа (с оговоркой В7).
- п.4 шрифты самохост, отзывы дословно.
- п.5 матрица 3840…320 и скриншоты глазами до показа.
- Инфраструктура: браузер и тяжёлые картинки — на NVR (`BTC-Server-1`), не на VPS; `/tmp` на NVR чистить после.

## Решения
1. **Паспорт дизайн-системы** `specs/006-new-design-rollout/design-system.md` (волна 0): токены (`--md-*` из `style.css` и локальные переменные `hero-*`, `reviews`, `mastergruppa`), компоненты с путями к CSS-классам: кнопка `md-plate` (ink/orange), стеклянная плашка, графитовая полоса, бумажная карточка отзыва, карточки форматов с 3D, FAQ-аккордеон, CTA-билет, шкала заголовков и текста на 1440/390, тайминги движений и reduced-motion. Источник — код, каждая строка со ссылкой на файл:строку.
2. **CSS-стратегия**: новый общий файл `assets/css/nd-pages.css` (компоненты второстепенных страниц из паспорта) + при необходимости свой файл страницы. Старые `networking.css`, `landing.css`, `webinar.css`, `utility.css` не правим, пока на них висят непереведённые страницы; после последней волны — удалить неиспользуемые (grep по всем `index.html`). Главную и мастер-группу не переподключаем.
   Если компонент уже живёт в `home-blocks.css`/`reviews.css`/`formats.css` — подключать этот файл, а не копировать (один источник, реестр 26.09 «ассет в двух копиях»).
3. **Body-класс**: переведённая страница уходит с `webinar …` на `home <slug>` по образцу `/otzyvy/` и мастер-группы (`home mg`), чтобы работали правила `.home` нового дизайна. Побочные эффекты `.home` на стили проверить регресс-кропами.
4. **Сверка «до/после»** — `specs/006-new-design-rollout/check-parity.mjs` (Node без зависимостей, регулярки по HTML): режим `snapshot <out.json>` и `diff <before.json>`; пункты 1–9 spec §6. Снимок `baseline.json` снимается один раз с `new-design` до первой правки.
5. **Браузерная проверка** — Python Playwright на NVR по рецепту БЗ проекта (venv в `/tmp`, `chromium-headless-shell`, `libnss3`/`libnspr4` через `apt-get download` + `dpkg -x`, `LD_LIBRARY_PATH`); сайт — копией в `/tmp` NVR + `python3 -m http.server`; `mc.yandex.ru` — заглушка пустым 200. Рабочий скрипт снимков этой спеки: `scratchpad/shoot.py` (14 страниц × 1440/390 × обе темы + замеры), переиспользовать.
6. **Макет первого экрана** на каждую волну: вёрстка первого экрана в ветке (не картинка) + Refero-референсы; при необходимости — Codex image_gen по связке «Редизайн существующего» из CLAUDE.md. Показ владельцу — кропы 1440/390 × обе темы рядом с первым экраном главной (как стилевой эталон, не образец композиции).
