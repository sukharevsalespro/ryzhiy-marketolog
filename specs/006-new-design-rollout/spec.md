## 3. Правило владельца (ЖЁСТКО)

Из реестра переделок (30.09.2026, строки «как стандарт — главная» и «новый дизайн, а ты в старом»):
- Второстепенные страницы **соблюдают стиль главной**: шрифты и шкала, цвета (крем/оранжевый/чёрный/графит, градиент с глубиной), `md-plate`-кнопки, плашки и стекло, радиусы, 3D-объекты по месту, анимации и их тайминги (`--md-t-*`, `--md-ease`), шапка и подвал.
- **Композиция и первый экран у каждой свои** под её задачу. Главную не копировать: никаких «обложка как у главной с другим заголовком», полосы цифр «20 / 49 / 963 / 0,9», штампа и рукописи главной на каждой странице.
- Эталон стиля — только страницы нового дизайна. В старые страницы до перевода не вкладываться (цены, блоки, OG — только после перевода или по отдельному «да»).

## 5. Требования

- **FR-1** Контент переносится дословно: тексты, цены, даты, отзывы (скрины как есть), юридические тексты. Блок нельзя удалить — только перекомпоновать; удаление любого блока — отдельный вопрос владельцу.
- **FR-2** Деньги и заявки: все ссылки `payform.ru/*`, `b2b.cbrpay.ru/*`, `t.me/*` (включая `?text=`), `max.ru/*`, механизм MAX «скопировать текст + тост», `data-msg-text`, `data-goal` — те же значения и то же число, если владелец не сказал иначе.
- **FR-3** Метрика: `metrika.js` подключён; цели по клику (`PAY_GOALS` по слагу ссылки, `data-goal`, `messenger_header`/`messenger_contacts` по контейнеру `header`/`footer`/`.messengers`/`.contact`/`#contacts`) срабатывают. Перенос кнопки мессенджера в другой контейнер меняет цель — сверять.
- **FR-4** SEO: `<title>`, `meta description`, единственный H1 (текст тот же), canonical, `robots`, OG (12 свойств) и Twitter (5), JSON-LD (типы и `offers` с ценами), хлебные крошки, `lang`, `alt` картинок, внутренние ссылки. `sitemap.xml` и `llms.txt` — без изменений URL.
- **FR-5** Стиль — только из токенов и компонентов нового дизайна (паспорт волны 0). Новый компонент — только если в паспорте нет подходящего, и с записью в паспорт.
- **FR-6** Каждая страница: 1440 и 390 без горизонтального скролла, матрица конституции (3840…320, планшет, альбомная) — дымовой прогон; 0 ошибок консоли; зоны нажатия ≥44px; `prefers-reduced-motion` отключает движение.
- **FR-7** Две темы по `prefers-color-scheme` (В1): светлая — крем, тёмная — графит, страница темнеет целиком (фон, полосы, карточки, текст, плашки, стекло), без белых «дыр», сторонние виджеты (Долями и т.п.) — в теме страницы (реестр 25.09).
- **FR-8** Шрифты только самохост, без внешних CDN (конституция п.4). CSP страниц не ослаблять.

## 6. Чек-лист сверки «до / после» (на каждую страницу, скриптом + глазами)

Скриптом (`check-parity.mjs`, задача T002): снимок до перевода → снимок после → дифф должен быть пустым по пунктам 1–9, кроме изменений, которые владелец разрешил явно.
1. `title`, `meta description`, `robots`, canonical.
2. H1: количество = 1, текст совпадает.
3. OG/Twitter: все свойства и значения (картинки — из ветки `og-cards` после её влития; до этого — те же).
4. JSON-LD: валидный JSON, набор `@type`, цены в `offers`, даты `Event`.
5. Ссылки оплаты: список уникальных `payform.ru/*` и `cbrpay.ru/*` + их количество.
6. Мессенджеры: `t.me/*` с `?text=`, `max.ru/*`, `data-msg-text`.
7. `data-goal` (значения и количество), подключение `metrika.js`.
8. Видимые цены (все «N ₽» в тексте страницы) и даты.
9. Внутренние ссылки (список href на `/…`), хлебные крошки, `alt` у всех `<img>`.

Глазами (Playwright на NVR): клик по каждой кнопке оплаты открывает ту же форму; TG открывает личку с тем же текстом; MAX копирует текст и показывает тост; цель уходит (перехват `ym(…, 'reachGoal', …)` при заглушке `mc.yandex.ru` пустым 200).

## 7. Приёмка каждой волны

- Процесс по CLAUDE.md: **макет одного экрана (первый экран страницы) → «да» владельца → вся страница → приёмка → «ок» на выкатку**. Без «да» на макет страницу целиком не верстать.
- Кропы `CMP-*` 2x: элемент новой страницы **рядом с тем же стилевым элементом эталона** (кнопка с кнопкой главной, плашка с плашкой, заголовок с заголовком, подвал с подвалом) — не «тот же блок» (реестр 30.09). 390 и 1440, светлая и тёмная.
- Чек-лист кропа: форма, радиус, подложка, рамка, кегль, цвет, иконки, отступы, выравнивание.
- Реестр переделок (`/root/knowledge-base/reference/design-redo-register.md`) — чек-лист «на что не наступить», особенно:
  - свечения/размытия гаснут внутри бокса, не режутся родителем (30.09);
  - фото человека: лицо целиком на 1440/1180/980/390, не под текстом и кнопками; hero-фото на 16:10, 16:9, 2560×1080, 3440×1440, 5120×1440 — ключевые зоны в кадре; размытая подложка >~20% ширины — брак (27.09, 30.09);
  - кадры не повторяются на странице, люди только в цвете, глаза видны (28.09);
  - карточки с текстом в покое ровные, 3D-наклон только на hover ≤3° (28.09);
  - предметы не наезжают на аватары (28.09);
  - карточки в ряду ровные по высоте, внутренняя сетка «эйтброу → главное → действие» (25.09);
  - на 390 не ужатый десктоп: кегль ≥15/1.4, мета в строку, зоны ≥44px (26.09);
  - после правки скрипта — headless-прогон с перехватом `pageerror` + `console.error`, `catch` не молчит (26.09);
  - даты — списком по датам, не «общее + исключения»; после смены данных грепать все места с датами (27.09);
  - никакой служебной прозы «как это устроено» на странице (25.09);
  - производительность: замер с CPU 4x и эмуляцией 390/Fast 4G; живые blur/backdrop-filter на анимациях запрещены (28.09);
  - перед вёрсткой сверить `git log` макета на снятые элементы (27.09).
- Отчёт исполнителя: «сделано X из N», изменённые файлы, раздел «Refero / Скилы», пути к кропам, открытые вопросы.
